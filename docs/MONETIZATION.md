# VEIN — BM & 수익화 전략

> **기준일:** 2026-09-06
> **목표:** 부수입 수준 (월 100~500만 원)
> **전략:** **콘텐츠 우선 → 구독**
> **전제:** `PROJECT_STATUS.md` 0장 — 이 제품의 1순위 목적은 여전히 "내가 쓰려고"다.
> 수익화가 그 목적을 훼손하면 수익화를 접는다.

---

## 1. BM을 고르는 기준

1인 개발자에게 진짜 제약은 **자본이 아니라 시간과 유입**이다.

부수입 목표(월 300만 원)를 역산하면 이렇게 된다.

| 가격 | 필요 유료회원 | 필요 MAU (전환율 3~5% 가정) |
|---|---|---|
| 월 9,900원 | 약 300명 | 6,000 ~ 10,000명 |
| 월 19,900원 | 약 150명 | **3,000 ~ 5,000명** |
| 월 49,900원 | 약 60명 | 1,200 ~ 2,000명 |

**MAU 3,000~5,000이 무서운 이유는 돈이 없어서가 아니라 그걸 만들 마케팅 시간이 없어서다.**
본업이 있고 개발도 혼자 하는 상태에서 그로스까지 하는 건 산술적으로 불가능하다.

그래서 BM 선택 기준은 하나로 좁혀진다.

> ### **"이 BM은 제품을 만드는 행위 자체가 마케팅이 되는가?"**

### 후보 평가

| BM | 유입 난이도 | 수익성 | 법적 리스크 | 구현 부담 | 종합 |
|---|---|---|---|---|---|
| 구독(SaaS) 단독 | 🔴 매우 높음 | 🟢 높음 | 🟡 중 | 🟡 중 | ⚠️ 유입 없으면 0원 |
| **콘텐츠 → 구독** | 🟢 콘텐츠가 유입 생성 | 🟢 높음 | 🟢 낮음 | 🟢 낮음 | ✅ **채택** |
| 거래소 리퍼럴 | 🟡 중 | 🟡 중 | 🔴 높음 | 🟢 낮음 | ❌ 아래 참조 |
| 오픈소스 + 후원 | 🟡 개발자 한정 | 🔴 낮음 | 🟢 매우 낮음 | 🟢 낮음 | 🤔 목표 미달 |
| B2B 라이선스 | 🔴 영업 필요 | 🟢 높음 | 🟢 낮음 | 🟡 중 | ❌ 1인 단계 불가 |

**리퍼럴 제외 사유**: 국내 증권사는 개인 제휴가 사실상 막혀 있고 업비트도 추천인 제도가 없다.
수익이 나오는 건 바이낸스·바이비트 같은 해외 거래소인데, **국내 미신고 가상자산사업자**라
홍보 자체가 특금법 위반 소지가 있다. 리스크 대비 실익이 낮다.

## 2. 채택 전략 — 콘텐츠를 먼저 팔고, 제품은 나중에 판다

### 2.1 이 제품의 진짜 자산은 코드가 아니다

지금 DB에 쌓이고 있는 것을 보라.

```
신호 410건 × 성과 추적(1h/4h/1d/3d/7d 수익률 · MFE · MAE)
  → 패턴별 적중률이 실측으로 누적되는 중
```

**이걸 하는 서비스가 없다.** TradingView도 안 한다. 대부분은 패턴을 보여주기만 하고
**사후 검증을 안 한다.** "이 패턴이 실제로 먹히는가"에 데이터로 답하는 곳이 없다.

그리고 결정적으로 — **본인이 실제로 이 패턴으로 매매하는 트레이더다.** 그게 콘텐츠의
신뢰성을 만든다. 이건 복제가 안 된다.

### 2.2 BM의 형태

```
[콘텐츠] 패턴 성과 리포트 발행 (주 1회)
   "ABC 패턴 1d봉, 최근 90일 표본 47건, 적중률 61%, 평균 +2.3%"
   "이말올은 코인에선 되는데 코스닥에선 안 된다 — 데이터로 확인"
              ↓ 유입을 만든다        (= 마케팅)
              ↓ 제품을 증명한다      (= 세일즈)
              ↓ 그 자체로 상품이다   (= 매출)
[제품] 무료 서비스로 유입 수용
              ↓
[전환] "직접 조건 만들고 알림 받으려면" → PRO
```

**콘텐츠가 마케팅이자 제품 증명이자 상품**이다. 세 가지를 한 번에 한다.

### 2.3 왜 이게 다른 후보보다 나은가

1. **유입 문제가 풀린다.** 구독 단독은 "좋은 제품 만들면 오겠지"인데 안 온다.
   콘텐츠는 검색·커뮤니티·SNS로 스스로 퍼진다.
2. **법적으로 훨씬 안전하다.** 리포트에 **종목 추천을 넣지 않고 통계만** 다루면 조언이 아니다.
   "ABC 패턴 적중률 61%"는 사실 서술이고, "지금 XX 사세요"가 조언이다. 선을 지키기 쉽다.
3. **데이터 라이선스 문제가 줄어든다.** 원본 시세 재배포가 아니라 **가공된 통계** 발행이다.
4. **검증이 공짜로 된다.** 리포트 구독자 수가 곧 ②층(`PROJECT_STATUS` 5.1)이 실재하는지에
   대한 답이다. 제품을 더 만들지 않고도 알 수 있다.
5. **실패해도 손실이 작다.** 안 먹히면 그냥 안 쓰면 된다. 변호사비도 라이선스비도 안 든다.

### 2.4 이 BM은 제1 전제와 충돌하지 않는다

리포트를 쓰려면 성과 데이터를 들여다봐야 하는데, **그건 어차피 내가 매매하려고 해야 하는
일이다.** 하던 일을 공개하는 것뿐이다.

## 3. 단계별 실행

```
0. [현재] 무료·초대제로 내가 쓴다                    ← PROJECT_STATUS Track A
        ↓ "데스크톱 터미널을 2주 이상 안 켰다"
1. 0~3개월 — 무료 콘텐츠
   주 1회 패턴 성과 리포트. 제품 개발은 Track A만.
        ↓ 구독자 증가 곡선 · 재열람률
2. 3~6개월 — 제품 유입 연결
   리포트 → 서비스 링크. 무료 가입 개방 + 후원 버튼.
        ↓ 리포트→가입 전환율 · 후원자 비율
        ↓ (후원자 비율 0.1% 미만이면 여기서 멈춘다)
3. 6개월~ — 유료화 판단
   · 리포트 구독자가 붙었다  → 콘텐츠 유료화 (규제 부담 최소)
   · 제품 사용률이 높다      → PRO 구독 (5장)
   · 둘 다                   → 번들
```

**핵심은 3단계 전에 멈출 수 있다는 것이다.** 변호사비와 데이터 라이선스 비용을 쓰기 전에
답이 나온다.

## 4. 코드로 뭘 바꿔야 하나

### 단계 1 (0~3개월) — ✅ 완료

리포트를 쓸 수 있으면 된다. 제품은 건드리지 않는다.

| 항목 | 상태 |
|---|---|
| **성과 요약 기간 필터** (`from`/`to`) | ✅ `ba69ab0` |
| **월별 집계** (`bucket=MONTH`) | ✅ `ba69ab0` |
| score 구간별·시장 교차 분석 | psql 직접 조회로 충분. 반복이 지겨워지면 그때 |

```bash
# 최근 90일 ABC 패턴 적중률
GET /api/v1/signals/performance/summary?type=ABC&horizon=1d&from=2026-06-08T00:00:00Z

# 패턴별 적중률 월별 추이
GET /api/v1/signals/performance/summary?horizon=1d&bucket=MONTH
```

> **단계 1의 나머지 3개월은 코드가 아니라 리포트를 쓰는 데 쓴다.**

### 단계 2 (3~6개월) — 여기가 실제 작업

#### 🔴 ① 회원가입 API가 없다 ★★최우선

```
AuthController: login / refresh / logout  ← 이게 전부
```

계정을 만들 방법이 **DB 직접 INSERT뿐**이고 `users.status` 기본값이 `PENDING`(승인제)이다.
**지금 구조로는 공개 베타 자체가 불가능하다.** 콘텐츠로 사람을 데려와도 받을 그릇이 없다.

- `POST /auth/signup { email, password }`
- 이메일 중복 검사 (`ux_users_email` 인덱스 존재), BCrypt (`AuthService`에 인코더 존재)
- **가입 즉시 `APPROVED`** — 단, `vein.signup.auto-approve: true` 플래그로 언제든 승인제 복귀
- 가입 rate limit (IP당 시간당 N건) — 없으면 봇 가입으로 DB가 오염된다

*공수: 반나절~1일*

#### 🔴 ② 비로그인 공개 엔드포인트 ★★

현재 `SecurityConfig.PUBLIC_ENDPOINTS`는 login/refresh/system-status/ws/swagger뿐이다.
**콘텐츠에서 링크를 눌러 들어와도 로그인 벽을 만나고, 유입이 거기서 죽는다.**

`"/api/v1/public/**"` 를 열되 — **공개하는 것은 "가공 통계"만이다.**

| 공개 ⭕ | 공개 ❌ |
|---|---|
| 성과 요약 (적중률·표본수·평균수익률) | 원시 캔들·시세 |
| 패턴별·시장별·월별 통계 | 개별 신호 상세 |
| 리포트에 인용한 집계 | 종목 목록·검색 |

**법적으로** 가공 통계는 재배포가 아니라 저작물에 가깝고, **상업적으로** 원시 데이터를 다
열면 가입할 이유가 없어진다.

`PublicStatsController` + **레이트리밋 필수** (현재 API 전체에 없음 — 외부 provider용
Resilience4j만 있다). *공수: 1~2일*

#### 🟡 ③ 유입 추적 ★

어느 리포트가 가입을 만들었는지 모르면 콘텐츠를 개선할 수 없다.

```sql
ALTER TABLE users ADD COLUMN signup_source VARCHAR(64);    -- utm_source
ALTER TABLE users ADD COLUMN signup_referrer VARCHAR(255);
```
*공수: 2시간*

#### 🟡 ④ 후원 링크 ★

FE 정적 링크(Buy Me a Coffee 등) + 랜딩·설정 하단. **기능 차등 절대 없음** (6장 참조).
측정은 `후원자 수 ÷ 가입자 수` — 초기엔 플랫폼에서 수동 집계로 충분. *공수: 1시간*

#### 🔴 ⑤ FE 랜딩 페이지 ★★

현재 `/`는 `require-auth`로 막혀 있다. 비로그인 랜딩이 필요하다.
- 제품 한 줄 설명 + 스크린샷
- **실측 적중률을 그대로 노출** (`/public/...`) ← 가장 강력한 세일즈
- 가입 CTA + 리포트 구독 링크

*공수: 2~3일*

> **단계 2 총 공수: 1~2주.** 단, **"리포트 구독자가 실제로 붙는다"가 확인된 뒤** 착수한다.
> 안 붙으면 만들 필요가 없다.

## 5. 단계 3 — 유료화 설계 (6개월 뒤 판단, 지금 착수 금지)

> 이 장은 **3단계 진입 조건을 충족했을 때만** 꺼낸다. 조건: 리포트 구독자가 붙었고,
> 후원자 비율이 0.5%를 넘었으며, PRO 후보 기능의 실사용률이 확인됨.

### 5.1 가르는 기준 — "조언 vs 도구"

```
패턴 신호(조언)      → 무료. 전부 연다.
자동화·검증(도구)    → 유료. 여기서 돈을 받는다.
```

**왜 신호를 무료로 두는가 — 두 이유가 겹친다.**

1. **법적**: "대가를 받고 투자판단에 관한 조언을 제공"하는 구조를 만들지 않는다
2. **상업적**: 신호는 봐도 **언제 뜨는지 모르면 못 쓴다.** 실질 가치는 알림 주기와 자동
   평가에 있다. 신호를 열어도 PRO 매력이 줄지 않고 오히려 유입 경로가 된다

### 5.2 티어표 (초안)

| 기능 | FREE | PRO (월 19,900원) |
|---|---|---|
| **— 조언 레이어 (전부 무료) —** | | |
| 4시장 시세·캔들·차트·지표 | ✅ | ✅ |
| 패턴 신호 열람 (ABC·TOP·IMALOL) | ✅ **전체** | ✅ 전체 |
| Pattern Score · Explain · Risk Guard | ✅ | ✅ |
| 속보 · 데이터 탭(TVL·유통량·테마·펀비차익) | ✅ | ✅ |
| **— 도구 레이어 (과금 대상) —** | | |
| 관심종목 | 20종목 | 무제한 |
| 알림 규칙 | 3개 · 쿨다운 최소 60분 | 무제한 · 쿨다운 최소 5분 |
| 백그라운드 웹푸시 | ✖ | ✅ |
| 조건검색 즉시 실행 | 일 5회 | 무제한 |
| 조건검색 저장식 | 2개 · 일 1회 평가 | 무제한 · 15분 주기 평가 + 매칭 알림 |
| 백테스트 | 월 10회 · 결과 7일 | 무제한 · 영구 |
| 워크포워드 IS/OOS 검증 | ✖ | ✅ |
| 전략 저장·재실행·히스토리 | 1개 | 무제한 |
| 모의투자 | 현물 1계좌 | 다계좌 · 선물/레버리지/부분청산 |
| 신호 성과 히스토리 | 최근 7일 | 전체 + 패턴별 적중률 |
| 강제청산 스트림 | 지연 스냅샷 | 실시간 + 급증 알림 |
| 틱띄기 · CSV 내보내기 | ✖ | ✅ |

**방어 논리**: PRO 항목에 "무슨 종목을 사라"가 **하나도 없다.** 전부 *더 자주 평가하고 ·
더 많이 저장하고 · 더 길게 보관하고 · 더 정교하게 검증하는* 것이다. 판단 주체는 끝까지
사용자다.

### 5.3 2차 방어선 — 코인/주식 분리

법률 검토 결과 5.2만으로 부족하다는 판단이 나오면, **주식(US·KOSPI·KOSDAQ)을 유료 범위에서
제외**한다. 가상자산은 자본시장법상 **금융투자상품이 아니라** 자문 규제 대상 밖이다.
기획서 26.1의 "MVP 핵심 시장은 코인"과도 정합적이다.

**부수 효과**: 주식을 빼면 **yfinance / pykrx 라이선스 문제도 같이 줄어든다**
(상업적 재배포 이슈의 대부분이 주식 소스에서 나온다).

> ⚠️ 회색지대다. 코인 리딩방 단속이 강화되는 흐름이고 입법 논의도 진행 중이다.
> **변호사 확인 + 금감원 비조치의견서**가 사실상 필수다.

### 5.4 DB 설계 (V23 초안)

`users.role`은 **권한**(TESTER/SUPER_ADMIN)이고 **과금 플랜과 다른 축**이다.
role에 PRO를 끼워 넣지 않는다.

```sql
ALTER TABLE users ADD COLUMN plan VARCHAR(16) NOT NULL DEFAULT 'FREE'; -- FREE|PRO|UNLIMITED
ALTER TABLE users ADD COLUMN plan_expires_at TIMESTAMPTZ;
UPDATE users SET plan = 'UNLIMITED' WHERE role = 'SUPER_ADMIN';

CREATE TABLE subscriptions (            -- 원장. UPDATE 하지 않고 append
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  plan VARCHAR(16) NOT NULL,
  status VARCHAR(16) NOT NULL,          -- ACTIVE|CANCELED|EXPIRED|PAST_DUE|REFUNDED
  period VARCHAR(8) NOT NULL,           -- MONTHLY|YEARLY
  amount NUMERIC(12,2) NOT NULL,
  currency VARCHAR(8) NOT NULL DEFAULT 'KRW',
  pg_provider VARCHAR(24), pg_billing_key VARCHAR(128), pg_order_id VARCHAR(64),
  started_at TIMESTAMPTZ NOT NULL,
  current_period_end TIMESTAMPTZ NOT NULL,
  canceled_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_subs_user_status ON subscriptions(user_id, status);

CREATE TABLE usage_counters (           -- 과금 근거이므로 Redis 아닌 영속 저장
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  metric VARCHAR(32) NOT NULL,
  bucket DATE NOT NULL,
  count INT NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, metric, bucket)
);

CREATE TABLE payment_events (           -- PG 웹훅 멱등 처리
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  provider VARCHAR(24) NOT NULL,
  event_id VARCHAR(128) NOT NULL,
  event_type VARCHAR(48) NOT NULL,
  payload JSONB NOT NULL,
  received_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (provider, event_id)
);
```

- `users.plan`은 캐시다. **진실은 `subscriptions`** — 불일치 시 배치로 정정
- 결제 실패는 즉시 강등하지 않고 `PAST_DUE` + **유예 3~7일**

### 5.5 게이팅 지점

서비스 메서드가 이미 전부 `Long userId`를 받아 삽입 지점이 깨끗하다.

| 대상 | 위치 | 검사 |
|---|---|---|
| 조건검색 즉시 실행 | `ConditionScannerService.run()` | ⚠️ **현재 `userId`를 안 받음 — 시그니처 추가 필요** + 일 5회 |
| 조건검색 저장식 | `ConditionScannerService.save()` | 개수 한도 |
| 저장식 평가 주기 | `ConditionScannerScheduler` | 플랜별 주기 분기 |
| 백테스트 | `BacktestService.run()` | 월 10회 + 워크포워드 PRO 전용 |
| 전략 | `StrategyService.create()` | 개수 한도 |
| 알림 규칙 | `AlertService.create()` | 개수 + `cooldownSec` 하한 |
| 웹푸시 | `WebPushService.subscribe()` | PRO 전용 |
| 모의투자 | `PaperTradingService.createAccount()` / `createOrder()` | 계좌 수 · 선물 PRO 전용 |
| 신호 성과 | `SignalService` 성과 조회 | FREE는 7일 절단 |
| 틱띄기 · 청산 실시간 | `ScalpController` · `LiquidationController` | PRO 전용 |

새 패키지 `com.vein.billing`: `Plan` · `PlanLimits` · `PlanService` · `UsageService` ·
`SubscriptionService` · `BillingWebhookController`.
`ErrorCode`에 `PRO_REQUIRED`(403) · `PLAN_LIMIT_EXCEEDED`(429) 추가.

### 5.6 관리자는 모든 한도를 우회한다

운영자(=나)는 **모든 기능을 제한 없이** 쓸 수 있어야 한다. 내가 못 쓰는 도구를 파는 건
말이 안 되고 장애 대응·검증도 불가능하다.

```java
public Plan currentPlan(Long userId) {
    User u = userRepository.findById(userId).orElseThrow(...);
    if ("SUPER_ADMIN".equals(u.getRole())) return Plan.UNLIMITED;   // 결제 상태 무관
    if (u.getPlan() == Plan.UNLIMITED) return Plan.UNLIMITED;
    if (u.getPlan() == Plan.PRO && isExpired(u.getPlanExpiresAt())) return Plan.FREE;
    return u.getPlan();
}

public void checkQuota(Long userId, Metric metric) {
    if (planService.currentPlan(userId) == Plan.UNLIMITED) return;  // 카운터도 안 올린다
    ...
}
```

- `UNLIMITED`는 **`PRO`의 상위** — enum 순서를 `FREE < PRO < UNLIMITED`로 두고 `atLeast()` 비교
- 구독 만료 배치가 `SUPER_ADMIN`을 강등시키지 않도록 쿼리에서 제외
- 부여/회수는 **`audit_logs`에 기록** (`AuditService` 기존재)
- Admin 화면(`/admin/users`)에 **플랜 수동 변경** — 테스터 부여, 환불·장애 보상 연장에 필수

> ⚠️ `UNLIMITED`를 남발하면 유료 전환 데이터가 오염된다. 지인·테스터는 `PRO` +
> `plan_expires_at` 만료일로 주고, `UNLIMITED`는 운영자 본인으로 제한한다.

### 5.7 결제 연동

| 항목 | 선택 |
|---|---|
| PG | 토스페이먼츠 또는 포트원 — 개인사업자 가입 가능, 빌링키 정기결제 지원 |
| 방식 | 빌링키 기반. 카드 정보 **자체 저장 금지** (PG 토큰만) |

| 실패 | `PAST_DUE` → 유예 3~7일 → 재시도 → `EXPIRED` 강등 |
| 환불 | 디지털 콘텐츠 청약철회 예외를 약관에 명시 + 미사용 기간 일할 환불 정책 |

## 6. 후원 모델 — 대체재가 아니라 전 단계

### 🟢 법적 이점

- 유사투자자문업 정의가 **"일정한 대가를 받고"** 를 요건으로 한다. 후원이 **반대급부 없는
  자발적 지급**이면 대가성이 부정될 여지가 크다 → 자문 규제가 발동하지 않는다
- **통신판매업 신고 불필요**, 청약철회·약관 부담 대폭 감소

### 🔴 결정적 조건 — 후원자에게 아무것도 더 주면 안 된다

| 안전 | 위험 |
|---|---|
| GitHub Sponsors · Buy Me a Coffee 스타일 | **Patreon식 티어별 혜택** |
| 이름 표시 정도까지 | **후원자 전용 기능·신호·알림 주기** |

**"후원하면 PRO 기능"은 이름만 후원이지 법적으로는 유료 구독이다.** 후원 모델을 택하려면
기능 차등을 **완전히 포기**해야 하고, 그러면 5장 티어 설계와 양립하지 않는다.

### 🟡 세금은 낸다

반복적·계속적 후원은 증여가 아니라 **사업소득 또는 기타소득**이다(국세청은 유튜브 슈퍼챗
등을 이 기준으로 판단해 왔다). 일정 규모를 넘으면 사업자등록도 필요하다.

### 🔴 데이터 라이선스는 나아지지 않는다

무료 서비스라도 외부 API 약관의 재배포 제한에는 걸리고, **후원을 받으면 "상업적 이용"으로
인정될 소지가 커진다.** 7장 체크리스트는 후원 모델에서도 유효하다.

### 🔴 수익 규모가 자릿수가 다르다

한국은 개인 개발자·오픈소스 후원 문화가 약해 **월 수만~수십만 원** 선에서 형성된다.
**부수입 목표로는 사실상 달성 불가하다.**

### ✅ 진짜 쓸모 — 지불의사 측정

3장 2단계에 후원 버튼을 붙이면 **규제·결제·약관 부담 없이 "돈을 낼 의사가 있는가"를
측정**할 수 있다.

- 보는 지표는 **후원 금액이 아니라 후원자 비율**
- MAU 대비 **0.5% 초과** → 유료 전환 시 3~5% 전환율을 기대할 근거
- **0.1% 미만** → 유료화하지 않는 게 맞다. 규제·라이선스 비용을 회수 못 한다

| 모델 | 법적 부담 | 예상 수익 | 목표 적합도 |
|---|---|---|---|
| 무료 + 후원 단독 | 낮음 | 월 수만~수십만 원 | ❌ 목표 미달 |
| **무료 + 후원 → PRO 전환** | 낮음 → 높음 | 단계적 | ✅ **채택** |
| 처음부터 PRO 유료 | 높음 | 월 100~500만 원 | ⚠️ 검증 없이 비용 선지출 |

> 만약 "돈 버는 것보다 규제 안 걸리는 게 더 중요하다"로 목표가 바뀌면, **후원 단독으로
> 끝내는 것도 완결된 선택**이다. 그때는 5장 티어 설계를 폐기한다.

- ❌ **"추천 종목" 표현** — 코드·UI 문구 금지어로 관리. **"탐지된 후보"로 통일**

## 9. 냉정한 전제

- 필요 MAU 3,000~5,000은 개인 개발자에게 작은 숫자가 아니다. **콘텐츠 없이는 안 된다**
- 데이터 라이선스 비용이 수익을 잠식할 수 있다 — **3단계 전에 비용을 먼저 계산할 것**

- **이 전부가 "내가 쓰려고 만든다"는 제1 전제와 충돌하기 시작하면, 수익화를 접는 것도 정답이다**
